Post-Production

Shoot day  →  editor's timeline

Sibling plugin to creative-studio-pipeline. Turns shot footage and audio files into a Premiere-ready first cut with three BGM options, a synced audio track, on-demand B-roll and mograph alphas — reaching 70 – 80% of a first cut in one day, so the editor's Premiere Pro session starts already loaded.

01

What Enters Post

Two arrivals converge in the intake bay: the release package from the pre-prod plugin (the paper trail) and the crew's Drive folder (the physical shoot output). Intake refuses to advance if either side is missing.

From pre-prod release

GATE C · CLOSED
  • script.md — final approved
  • storyboard.json — shot list with frame refs
  • concept-breakdown.xlsx — talent, prop, location line items
  • call-sheet-day-*.pdf — one per shoot day
  • storyboard/v{n}/P*.png — the actual visual panels

Bound by hash to the pre-prod release. A change upstream reopens Post at intake.

From the shoot

DRIVE FOLDER
  • footage/day-*/A001_C*.mov — camera masters
  • footage/day-*/proxies/ — editing proxies (optional)
  • audio/lav/ — talent lavalier tracks
  • audio/boom/ — boom mic capture
  • audio/ambient/ — room tone, wild lines
  • slates/ — clapper reference frames

Ingest computes checksums on every file. A missing take is a question, not a silent skip.

Human declarations

XX ITEMS
  • Aspect ratio target (16:9 / 9:16 / 1:1)
  • Deliverable duration (30s / 60s / cutdowns)
  • Reference cut, if one exists
  • Colour direction — LUT / grade note
  • Audio hero — is this VO-led or picture-led?

The pipeline never fills an XX for you. A blank stays a question.

03

Agents · Ten Seats

Ten director agents, seven doing production work and three doing coordination. Same convention as pre-prod: each director wraps one or two skills; the orchestrator only walks the table and verifies files on disk.

00

Orchestrator

Walks the 12-state table, checks output artefacts exist, advances state through the two gates.

01

Post-Intake Director

Validates the pre-prod release package plus the shoot Drive folder plus the human declarations.

02

Ingest Director

Reads the Drive folder, catalogs clips and audio, computes checksums, emits manifest.

03

Sequence Director

Frame-matches the storyboard against the manifest, picks best takes, emits rough EDL.

04

BGM Supervisor

Reads script tone and storyboard beats, requests three candidates, presents to human.

05

Audio Engineer

Owns VO drop-in and the sync pass — VO, BGM and SFX aligned to picture.

06

B-Roll Director

Handles on-demand B-roll requests. Saves to folder. Does not auto-splice into cut.

07

Mograph Director

Infographic lower thirds and mograph reveals as alpha-channel exports via Remotion.

08

Premiere Packager

Builds the FCPXML timeline and the bundle folder tree for editor handoff.

09

Review Director

Runs the combined picture+audio rubric before Gate A. Blocks or clears. Never approves.

05

Tools · What Actually Does the Work

Each rack lists the tool by name with its role. Video and image generation go through the existing 3echo AgentC MCP (no new server-side tools required — every call is against an endpoint pre-prod already uses). Everything else is local execution — ffmpeg, remotion, python.

Video generation

MCP · 3echo AgentC
  • SeeDance B-roll · main engine
  • 9 image refs / job continuity
  • 3 video refs, 3 audio refs per job

create_video_job on the same AgentC MCP pre-prod uses. The B-roll skill tags the output in the manifest; there is no separate server tool. Whatever engines AgentC adds later, we inherit for free.

Image generation

MCP · 3echo AgentC
  • GPT image models stills · plates
  • 16 image refs / job continuity
  • flat 1 credit / image no per-model quote

create_image_job on the AgentC MCP. Slate frames, mograph plate art, storyboard-continuity thumbnails. Same tool pre-prod's make-image skill uses today.

Audio generation

MCP · external
  • ElevenLabs VO · scratch + final
  • Suno / Musicbed / Artlist not wired · client supplies BGM

ElevenLabs is connected for scratch VO and transcription; final VO uses talent takes from the shoot. No music service is wired: the client supplies the BGM files and the supervisor shortlists three.

Sequence retrieval

OM · lib/clip_embedder
  • CLIP ViT-L/14 frame embedding
  • storyboard → footage semantic match
  • best-take ranking per storyboard panel

CLIP matching, pointed at shoot footage instead of stock libraries. Beats naive frame diff.

Motion graphics

OM · remotion-composer
  • Cinematic titles · reveals
  • Explainer infographic
  • TalkingHead lower thirds
  • CollageBurst, LyricOverlay extras

Templates ship with the 3echo Motion composer. Alpha exports (ProRes 4444) drop into Premiere. Not a rewrite.

Assembly + sync

LOCAL · ffmpeg
  • ffmpeg transcode · concat · sync
  • ffprobe clip metadata · timecode
  • lib/media_profiles codec presets · OM
  • librosa tempo · planned, not wired

Runs on your machine. No cloud round-trip. The money shot Ken flagged.

Gate records

LOCAL · ours
  • record-approval.js verdict → approvals/*.json
  • board-sync.js pull board lock → hash-bound record
  • check-approval.js refuses a changed file

Hash-bound records survive a resume.

Delivery format

LOCAL · python (ours)
  • FCPXML 1.10 Premiere-importable
  • build-fcpxml.py EDL + synced track → timeline
  • opentimelineio, rsync planned, not built

Written by us — a rendered MP4 is not enough; we need a Premiere project.

05·5

Frame vs Engine

Where the code comes from. Honest split so we don't rewrite work that already exists, and we don't inherit shapes that fight JGN's workflow.

The Frame

WE BUILD
  • Intake + release-package validation agency-specific
  • 10 director agents match pre-prod
  • 2-gate structure + board-sync team reviews
  • Storyboard-driven sequencing from pre-prod
  • FCPXML packager editor handoff
  • Post Control artifact board sibling to the Pre-production board
  • Runtime scripts (22) route, plan, state, records, bundle

The shape agency post actually has. Not autonomous — the editor keeps control.

The Engine

OM · REUSED
  • lib/clip_embedder semantic retrieval
  • remotion-composer 5 mograph templates
  • lib/media_profiles codec awareness

Proven, working code. Footage-repurpose plugin already runs on this pattern.

What we do NOT lift

OM · SKIP
  • executive-producer autonomy too hands-off
  • documentary-montage pipeline CLIP-thematic, not storyboard
  • retrieval from Pexels / NASA we shoot our own
  • delivery renderer → MP4 we need FCPXML
  • lib/checkpoint, delivery_promise present, not called

Other pipelines' opinions fit their use case; they'd fight ours. Take the libs, leave the doctrine.

Direct answer
Q

Does it have a locally-executed editor?

No — and that's deliberate. The pipeline does not open a video editor of its own. It produces an FCPXML timeline and an asset bundle that Premiere Pro imports in one step, and the human editor finishes the pass there.

What runs locally is the assembly engine — ffmpeg for the sync pass, the 3echo Motion composer for mograph, a CLIP matcher for storyboard-to-footage matching, our own python for the FCPXML build. These do the mechanical work: transcode proxies, align VO to picture, retrieve best takes, build alpha-channel overlays, write the timeline XML. They do not render a final master.

Why not build an editorPremiere Pro is where the editor's craft lives. Replacing it means competing with three decades of workflow. Wrong fight.
Why FCPXMLPremiere, DaVinci Resolve and Final Cut all import it losslessly. One handoff format, three possible editors, no lock-in.
Why local executionSync passes on multi-gigabyte footage don't survive a cloud round-trip. ffmpeg and CLIP retrieval on your machine are a hundred times faster than a hosted job.
The 70 – 80% rulePipeline reaches a rough cut with sync and BGM. Editor picks up from there — punch-ins, slow-mo, colour, titles, the touch work only a human should do.
